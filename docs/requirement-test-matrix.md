# Requirement-to-test matrix

Test names are exact; the offline suite is run by `cargo test --all-targets --locked`.
The public-network test is separate and ignored unless `RUN_LIVE_TESTS=1` is set.
`scripts/check_matrix_tests.py` resolves every reference in the evidence
columns against `cargo test --all-targets -- --list` and fails on a name that
does not exist or is ambiguous. Grouped references are expanded; a module
wildcard must match at least one test.

Gate evidence for the submitted baseline is recorded in
[`final-verification-2026-10-25.md`](final-verification-2026-10-25.md);
this branch's results are recorded in
[`verification-2026-10-30-continuity.md`](verification-2026-10-30-continuity.md)
and in
[`verification-2026-11-01-journal-hardening.md`](verification-2026-11-01-journal-hardening.md).

## Cross-cutting evidence

| Claim | Test / evidence | What it establishes, and what it does not |
|---|---|---|
| The capture contains every update the mock exchange delivered in steady state | E2E `steady_state_history_matches_mock_exchange_truth` | Compares captured delta count, side, price, quantity, per-update resulting book, and final book against the mock's independent history. It does not prove anything about the live exchange. |
| A source switch is anchored by a full snapshot before resumed deltas | E2E `single_socket_loss_fails_over_and_emits_anchoring_snapshot`; `collector::state::tests::clocked_failover_anchors_resumed_deltas_and_preserves_receive_times` | The snapshot equals the shadow's truth at loss and later deltas apply to it. It does not prove a live venue's shadow is complete. |
| A full outage exposes an uncovered interval instead of silently claiming completeness | E2E `full_outage_recovery_exposes_the_uncovered_interval` | Updates during the outage are absent; `verify` reports the pre-outage deltas disagreeing with the recovery snapshot. |
| Discovery churn retires and adds symbols without mixing their histories | E2E `discovery_churn_retires_and_adds_symbols` | The retired symbol ends with an empty snapshot; the new symbol starts with a snapshot and its own deltas; `verify` accepts the retirement boundary. |
| A silent subscription is detected and repaired | E2E `silent_subscription_is_detected_and_repaired` | Suppressed updates trigger a stale probe that cycles the subscription in place; the repair book arrives as a fresh exchange snapshot on the same connection, with no reconnect or source switch. It does not prove detection of every venue-specific silence pattern. |
| A missed update is detectable when a later snapshot exposes it | E2E `negative_control_missing_update_is_detected_by_verify` | `verify` exits invalid when a later non-empty snapshot disagrees with the reconstructed book; `verify` is not a completeness oracle by itself. |
| Timestamps are actual receive times and are not clamped | `collector::state::tests::snapshot_anchors_delta_application_in_per_symbol_order`; `collector::state::tests::clocked_failover_anchors_resumed_deltas_and_preserves_receive_times`; E2E `assert_delta_receive_times_monotonic` | Event receive timestamps are preserved exactly. Generated snapshots are stamped with the wall-clock generation time; a failover snapshot never precedes the replacement book's last receive time and is not rewritten. |
| Output order is processing order, not global timestamp order | `collector::state::tests::cross_symbol_output_order_is_processing_order_and_not_globally_sorted`; E2E `assert_per_symbol_anchor` | Per-symbol snapshots anchor subsequent deltas. Cross-symbol timestamps may regress; consumers must preserve file order. |
| `verify` handles retirement/empty books without false mismatches | `verify::tests::empty_snapshot_is_a_retirement_boundary_not_a_mismatch` | An empty snapshot is counted as a boundary, not compared level-by-level. It cannot prove a suppressed update that emptied a book was observed; only a later non-empty snapshot can. |
| Subscription scale is tested beyond discovery | E2E `mock_subscription_scale_across_shards` | 1,000 symbols, 4 shards, 2 replicas, 8 loopback WebSockets, 250 symbols per socket, 2,000 subscription entries. It does not establish live venue limits or 548,942 simultaneous subscriptions. |
| Scale envelope measured at 1k/5k/25k/100k symbols | E2E `opt_in_scale_run` (ignored; run with `SCALE_SYMBOLS=N`) | Measured connect+subscribe, anchor, settle times, RSS, output bytes. 100k: 20 shards, 40 connections, 200k subscriptions, 5.0s total, 696 MB RSS. Does not establish live venue limits or full-universe 548,942 tokens. |
| Raw frames survive, verify, and fail without dropping | `journal::tests::*`; E2E `journal_finalizes_and_verifies_on_graceful_shutdown` | Exact payloads, checksums, manifest, per-source order, queue saturation, write/sync/finalize faults, truncation, corruption, and partial shutdown are covered offline. The SBE output is unchanged. It does not establish live journal throughput or retention behavior. |
| A latched journal failure is terminal and finalization stays bounded | `journal::tests::queue_saturation_then_shutdown_stays_failed`, `journal::tests::concurrent_producers_stop_after_failure`, `journal::tests::blocked_writer_bounds_shutdown`, `journal::tests::blocked_writer_bounds_abort`, `journal::tests::finalize_reply_timeout_stays_incomplete`, `journal::tests::repeated_concurrent_and_dead_writer_shutdowns_are_bounded` | Saturation through the production `shutdown` path leaves the run failed with `verify` incomplete; producers reject after the latch; every shutdown/abort phase is bounded by one deadline. Transport-level idle events are out of scope; a frame written during socket teardown is a transport loss, not journal accounting. |

## Not claimed

- **Kalshi live validation.** No authorized credentials were supplied. The
  signing, codec, discovery, and mock-session tests are not a live handshake.
- **Full-universe simultaneous subscription.** The 548,942-token sweep is a
  discovery result. The tested subscription envelope is the 1,000-symbol
  loopback E2E above; the configured limits are separate.
- **Global chronological output.** The writer preserves processing order and
  actual receive timestamps. There is no bounded reordering buffer, and no
  claim that sorting by timestamp reconstructs the books.
- **Extension 4 causality.** The four latency files are single 60-second
  observations. Source-port/CDN hashing and Nagle/delayed-ACK explanations are
  hypotheses, not isolated mechanisms.
- **Live journal durability.** The raw-frame journal is verified by deterministic
  fault injection and mock-exchange scenarios, including a latched
  failure-state contract, deadline-bounded shutdown, exact per-payload
  ingress accounting, and isolated ext4 ENOSPC behavior. It has not been
  soaked on a live feed, filled a production volume, or exercised a
  power-loss boundary; retention and disk-watermark policies are not
  implemented. A checksum-valid journal proves the integrity of recorded
  payloads, not that the venue delivered every event.
